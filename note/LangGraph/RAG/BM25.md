# BM25 and Hybrid Search

## What is BM25?

**BM25 (Best Match 25)** is a classical keyword-based ranking algorithm — an evolution of TF-IDF.

It scores documents based on:

```
Score = Σ IDF(term) × (TF × (k1 + 1)) / (TF + k1 × (1 - b + b × docLen/avgDocLen))
```

| Component | Meaning |
|-----------|---------|
| **TF** | How often the term appears in the doc |
| **IDF** | How rare the term is across all docs |
| **k1** (~1.2-2.0) | Term frequency saturation |
| **b** (~0.75) | Document length normalization |

**Key behavior:** Exact keyword matching. "Python tutorial" finds documents containing those exact words.

---

## What is Vector Search?

Converts text to dense numerical vectors (embeddings) and finds documents by **semantic similarity**.

```
"How do I cook pasta?" ──► [0.2, 0.8, -0.3, ...]
                              ↓
                        cosine similarity
                              ↓
               finds "pasta recipe guide" ✓ (even without exact words)
```

---

## Why Use Both Together? (Hybrid Search)

They have **complementary weaknesses**:

| Situation | BM25 | Vector Search |
|-----------|------|---------------|
| Exact keyword match ("UUID-1234") | ✅ Great | ❌ Poor |
| Rare/specific terms ("FAISS index") | ✅ Great | ❌ May miss |
| Semantic meaning ("cheap" ≈ "affordable") | ❌ Misses | ✅ Great |
| Paraphrasing/synonyms | ❌ Misses | ✅ Great |
| Short queries with typos | ❌ Poor | ✅ Handles well |
| Out-of-vocabulary words | ❌ Fails | ✅ Usually ok |

---

## How Hybrid Search Works

**Reciprocal Rank Fusion (RRF)** — most common approach:

```python
# Each retriever returns ranked results
bm25_results    = [doc_A, doc_C, doc_B, ...]   # keyword ranking
vector_results  = [doc_B, doc_A, doc_D, ...]   # semantic ranking

# Combine scores
rrf_score(doc) = 1/(k + bm25_rank) + 1/(k + vector_rank)

# Final merged ranking considers both signals
```

## Real-World Example

Query: **"transformer architecture paper"**

```
BM25 finds:        "Attention Is All You Need" (exact words match)
Vector finds:      "BERT: Pre-training of Deep Bidirectional Transformers"
                   (semantically related even without exact words)

Hybrid finds:      BOTH ✅
```

---

## When to Use What

```
Keyword-heavy (product IDs, codes)  → BM25 alone may suffice
Conversational/semantic queries     → Vector alone may suffice
Production RAG / search systems     → Hybrid (best of both worlds)
```

Most modern RAG frameworks (LangChain, LlamaIndex, Weaviate, Elasticsearch) support hybrid search out of the box because it **consistently outperforms either method alone**.
